## 4. Key Technical Findings

### 4.1 SM2 Format Compatibility

**Encryption Format:**
- Java BouncyCastle outputs RAW C1C3C2 format: `04||x[32]||y[32]||C3[32]||C2[N]`
- GmSSL expects DER SEQUENCE format: `30||len||02||x_len||x||02||y_len||y||04||20||C3||04||C2_len||C2`
- **Solution:** C implementation includes `sm2_raw_c1c3c2_to_der()` function for automatic conversion

**Signature Format:**
- Both Java BouncyCastle and GmSSL use DER-encoded SEQUENCE {INTEGER r, INTEGER s}
- **No conversion needed** - formats are directly compatible

### 4.2 SM3/HMAC-SM3 Compatibility

- Both implementations produce **identical 32-byte output**
- No format conversion required
- HEX encoding is reliable for cross-language data exchange

### 4.3 SM4 ECB Mode Fix

**Issue Found:** Initial C implementation incorrectly used CBC mode with zero IV to simulate ECB
**Fix Applied:** Changed to true ECB mode by calling `sm4_encrypt()` on each 16-byte block independently

```c
// Before (INCORRECT - CBC mode)
sm4_cbc_encrypt(&ctx, iv, padded_data, padded_len / 16, ciphertext);

// After (CORRECT - ECB mode)
for (size_t i = 0; i < padded_len; i += 16) {
    sm4_encrypt(&ctx, padded_data + i, ciphertext + i);
}
```

### 4.4 PKCS7 Padding

- Both Java and C implementations use standard PKCS7 padding
- Padding is **fully compatible** between platforms
- Test data: 32-byte message + 16 bytes padding = 48 bytes ciphertext

## 6. Conclusions

### 6.1 Interoperability Status

| Algorithm | Interoperability | Notes |
|-----------|-----------------|-------|
| **SM2** | Full | Requires C1C3C2 to DER conversion for decryption |
| **SM3** | Full | Direct compatibility |
| **HMAC-SM3** | Full | Direct compatibility |
| **SM4-ECB** | Full | Requires true ECB mode (not CBC with zero IV) |

### 6.2 Recommendations

1. **SM2 Encryption:** Always use C1C3C2 RAW format from Java and convert to DER in C
2. **SM2 Signatures:** DER format is directly compatible - no conversion needed
3. **SM4 ECB:** Ensure both implementations use true ECB mode, not CBC simulation
4. **Character Encoding:** Use UTF-8 for all string operations
5. **HEX Encoding:** Reliable for cross-language data exchange

### 6.3 Known Limitations

- SM2 CBC mode not tested (only ECB mode tested)
- Large file encryption not tested
- Performance benchmarks not included
